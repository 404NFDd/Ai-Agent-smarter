# Code Style Skill

## 목표

새 코드가 기존 코드베이스 안에서 튀지 않게 하고, 단순한 변경을 단순하게 유지한다.

## 함께 적용하는 스킬

- 리팩터링이 포함되면 `../refactoring/SKILL.md`를 함께 적용한다.
- UI 스타일 변경은 `../frontend-ui/SKILL.md`를 함께 적용한다.
- 문서 문체나 예시 변경은 `../documentation/SKILL.md`를 함께 적용한다.

## 기본 원칙

- 기존 파일의 구조, 네이밍, import 순서, 에러 처리 방식을 우선한다.
- 한 번만 쓰는 코드를 위해 새 추상화를 만들지 않는다.
- 공통화는 중복이 실제 복잡도를 만들 때만 한다.
- 타입, schema, helper가 이미 있으면 새 규칙보다 기존 것을 사용한다.

## 주석 기준

- 코드가 이미 말하는 내용은 주석으로 반복하지 않는다.
- 함수에는 입력, 출력, 동작, 부작용, 예외를 주석으로 남긴다. 
- 복잡한 의사결정, 비즈니스 제약, 우회 이유만 짧게 설명한다.
- TODO는 담당자나 후속 조건이 분명할 때만 남긴다.

## 정리 기준

- 내가 만든 unused import, 변수, dead code는 정리한다.
- 기존 unrelated 변경이나 오래된 dead code는 요청 범위 밖이면 건드리지 않는다.
- 포맷터가 있는 프로젝트는 해당 포맷터 결과를 따른다.

## 완료 전

- 변경 파일에서 스타일이 주변 코드와 일관되는지 확인한다.
- lint 또는 typecheck가 있으면 관련 범위에서 실행한다.
