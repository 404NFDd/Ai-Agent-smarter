# Bugfix Debugging Skill

## 목표

증상을 재현하고 원인을 좁힌 뒤, 가장 작은 수정으로 회귀를 막는다.

## 작업 전 확인

- 실패 로그, 사용자 설명, 재현 단계, 기대 동작과 실제 동작을 분리한다.
- 최근 변경, 관련 테스트, 오류가 발생한 입력과 환경을 확인한다.
- 버그가 UI, API, DB, 보안 중 어디에 걸치는지 판단하고 관련 skill도 함께 확인한다.

## 디버깅 순서

- 가능하면 먼저 실패를 재현한다.
- 재현이 어렵다면 관찰 가능한 증거와 가설을 분리해 기록한다.
- 원인 후보를 하나씩 줄이고, 무관한 리팩터링은 하지 않는다.
- 수정은 실패 지점과 직접 관련된 코드에 한정한다.
- 같은 유형의 회귀를 막을 테스트나 검증을 추가한다.

## 금지

- 로그 없이 추측만으로 넓은 코드를 바꾸지 않는다.
- 실패를 숨기기 위해 테스트 기대값만 바꾸지 않는다.
- 사용자 변경으로 보이는 코드를 되돌리지 않는다.

## 완료 전

- 재현에 사용한 명령과 수정 후 재실행한 명령을 `QA.md`에 기록한다.
- 재현하지 못했거나 검증하지 못한 부분은 남은 위험으로 남긴다.
