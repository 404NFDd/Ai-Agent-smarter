# Testing Skill

## 원칙

- 버그 수정은 가능하면 먼저 실패를 재현한다.
- 수정 후 같은 검증을 다시 실행한다.
- 실행하지 못한 검증은 이유와 남은 위험을 남긴다.

## 작업 전 확인

- 프로젝트의 표준 test, lint, build 명령을 확인한다.
- 실패 로그가 있으면 원인과 증상을 분리해 읽는다.

## QA.md 기록 형식

```md
| 명령 | 결과 | 일시 | 메모 |
| --- | --- | --- | --- |
| npm test | 통과 | 2026-06-02 10:00 | 관련 테스트 통과 |
```

## 완료 전

- 최소한 변경 범위와 직접 관련된 검증을 실행한다.
- 실패가 남으면 최종 보고에 반드시 포함한다.
