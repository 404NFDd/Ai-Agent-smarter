# Documentation Skill

## 목표

문서가 코드와 같은 방향을 가리키게 만들고, 필요한 독자가 바로 다음 행동을 할 수 있게 한다.

## 작업 전 확인

- 기존 문서의 톤, 구조, 용어, 경로 표기 방식을 확인한다.
- 코드 변경이 사용자 사용법, API, 설정, 배포, 검증 명령에 영향을 주는지 확인한다.
- 템플릿 문서와 실제 적용 문서를 구분한다.

## 작성 기준

- 한글을 기본으로 쓰되, 코드 식별자와 명령은 원문을 유지한다.
- 문서는 실행 가능한 절차, 결정 이유, 제약 조건 중심으로 쓴다.
- 오래된 내용을 남길 때는 현재 기준과 충돌하지 않게 정리한다.
- 큰 작업의 결정 사항은 `CONTEXT.md` 또는 `DECISIONS.md`에 남긴다.

## 금지

- 코드와 맞지 않는 미래 기능을 문서에 확정적으로 쓰지 않는다.
- 요청받지 않은 문서 구조 확장을 하지 않는다.
- 예시 명령을 검증 없이 유일한 정답처럼 쓰지 않는다.

## 완료 전

- 수정한 문서의 링크, 경로, 명령이 현재 저장소 기준으로 맞는지 확인한다.
- 수정 파일 목록을 `MODIFIED_FILES.md`에 기록한다.
