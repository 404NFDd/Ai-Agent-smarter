# Review Skill

## 목표

칭찬이나 요약보다 버그, 회귀 위험, 보안 문제, 누락 테스트를 먼저 찾는다.

## 리뷰 순서

- 변경 의도와 실제 diff가 맞는지 확인한다.
- 사용자 입력, 권한, 데이터 변환, 에러 처리, 경계 조건을 우선 본다.
- 테스트가 변경 위험을 충분히 덮는지 확인한다.
- 성능, 접근성, 운영 로그, 배포 위험은 변경 범위에 따라 확인한다.

## 출력 형식

- findings를 먼저 쓴다.
- 심각도 높은 순서로 정렬한다.
- 각 finding에는 파일과 줄을 붙인다.
- 문제가 없으면 “발견한 문제 없음”을 명확히 말하고 남은 테스트 공백을 적는다.

## 금지

- 스타일 취향을 버그처럼 말하지 않는다.
- 코드 전체를 재설계하는 제안을 리뷰 결과로 섞지 않는다.
- 근거 없는 추측을 확정적 결론으로 쓰지 않는다.

## 완료 전

- 내가 놓칠 수 있는 실행 불가 테스트나 환경 제약을 함께 남긴다.
