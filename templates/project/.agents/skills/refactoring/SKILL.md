# Refactoring Skill

## 목표

외부 동작을 바꾸지 않고 코드의 이해 가능성, 중복, 변경 용이성을 개선한다.

## 작업 전 확인

- 리팩터링의 목표와 비목표를 명확히 한다.
- 현재 동작을 보호할 테스트나 수동 검증 방법을 찾는다.
- 기능 변경과 리팩터링을 가능한 한 분리한다.

## 구현 기준

- 작은 단계로 나누고 각 단계가 동작 보존인지 확인한다.
- 기존 public API, 데이터 계약, UI 동작을 유지한다.
- 중복 제거는 실제 변경 비용을 낮출 때만 한다.
- 새 abstraction은 이름, 책임, 사용 지점이 분명할 때만 만든다.

## 금지

- 리팩터링 중 새 기능을 섞지 않는다.
- 테스트 없이 넓은 구조 변경을 하지 않는다.
- unrelated 파일을 포맷팅하거나 재배열하지 않는다.

## 완료 전

- 기존 테스트 또는 동작 확인을 실행한다.
- 동작 변경이 의도적으로 포함됐다면 별도로 명시한다.
